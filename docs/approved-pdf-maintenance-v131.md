Forty-five view functions move into four readable native ES modules. Shared dependencies use getters for mutable route/filter/photo/comparison state, so navigation does not capture stale values. Stable home/service DOM reuse remains in the main application.

Only proven unreachable branches are removed: obsolete native renderers for protected standalone URLs, superseded generic contact/FAQ templates, and resort-only branches after unconditional resort/stay returns. The active chalet service list and shared contact/FAQ behavior are preserved in their maintained modules. No file is deleted. Old iframe assets, compatibility redirects, shared imagery, tests, build inputs and error/retry paths are retained when external or indirect use cannot be ruled out.

No production library or build framework is added. Browser-native imports and preload hints are generated by the existing builder. A temporary formatter/parser was used outside the repository to make source readable; it is not a production dependency. Formatting and module boundaries increase source whitespace, so this change does not claim a smaller uncompressed JavaScript byte count.

## Measured speed improvement

Previously, startup waited for successive code downloads before rendering: visit helper, catalogue data, order controller, then restaurant/message modules. Photos could only be requested after those dependencies and the first render.

Start the same code/data downloads together using native module/fetch preloads. Order initialization and visit-snapshot registration still complete before the first render, preserving early request taps and internal-navigation drafts. Preload the existing regular text font alongside the bold font. There are no duplicate JSON/module downloads in the recorded resource timeline and no new image preload hints, photo conversions, placeholders or deferred-photo policy.

Controlled comparison: three cold runs per route, Chromium at390×844, CPU4×, network latency120ms and download1.5MiB/s, local uncompressed HTTP server. Values are medians; they are not a promise for every guest/network.
